01 / GOAL

规范目标

本规范用于统一预充值产品中的颜色选择、颜色含义和变量使用方式，确保产品在不同页面、状态和终端中保持一致、清晰并具备良好的可访问性。

基础颜色变量

描述颜色本身，例如 blue/500，不承载界面语义。

语义颜色变量

描述颜色用途，例如 text/primary、stroke/default，供界面和组件使用。

引用原则业务界面和组件应引用语义颜色变量，不直接引用 Hex 色值或基础颜色变量。

03 / BRAND COLORS

品牌颜色使用

每个色彩家族具有明确职责，不跨越既定语义使用。

blue/500 · #176BFF

Blue / 品牌蓝

Blue 是产品的主色，用于表达品牌识别和主要交互。

推荐用于
  • 页面中的主要操作和关键入口。
  • 当前选中、激活或进行中的状态。
  • 重点数据、链接和信息提示。
  • 以蓝色为主导的品牌渐变。
避免用于
  • 错误、危险或不可逆操作。
  • 大面积正文文字。
  • 与多个高饱和颜色同时竞争视觉焦点。
teal/500 · #00D1B2

Teal / 辅助青绿

Teal 用于扩展品牌色彩，并传达活力、完成和正向感受。

  • 品牌辅助图形和渐变终点。
  • 成功、完成或可用状态。
  • 次级重点信息和数据图形。

Teal 不应与 Blue 形成同等级的主要操作按钮，除非语义上需要明确区分两类操作。

orange/500 · #F79400

Orange / Logo 橙

Orange 来源于西湖大学 Logo 色，应保持品牌关联和提示属性。

推荐用于
  • Logo 相关品牌点缀。
  • 警告、注意、等待或待处理状态。
  • 小面积图标、标签和数据强调。
避免用于
  • 大面积页面主色。
  • 与 Red 混用表达同一状态。
red/500 · #E5484D

Red / 功能红

采用 R1「清晰警示」方案，核心色为 red/500 #E5484D。

  • 表单校验错误。
  • 失败、危险和阻断状态。
  • 删除、撤销后不可恢复等高风险操作。
  • 需要用户立即注意的异常信息。

Red 不用于普通品牌装饰、成功状态或常规重点信息。

purple/500 · #9C28F0

Purple / 扩展紫色

Purple 作为扩展色使用，适用于分类、数据系列、特殊权益或实验性功能。除明确的分类体系外，不应把 Purple 作为主要交互颜色。

04 / COLOR SCALES

色阶使用规则

色阶表示视觉强度，不直接等同于组件状态。具体状态应通过语义变量映射基础色阶。

400–500图标、品牌色、默认状态、视觉锚点
600–700强调文字、按下状态、高对比图标
800–950深色背景、强对比文字和高强度状态

中性色使用规则

Neutral 用于文字、背景、描边和界面层级。

变量范围推荐用途
neutral/0–100页面背景、容器背景、浅色区域
neutral/200–300普通边框、输入框边框、分割线
neutral/400–500占位内容、辅助信息、禁用元素
neutral/600–700次要文字、常规图标、强调描边

08 / STATUS

状态颜色规范

每种状态建议同时定义背景、文字、图标和描边四类语义变量。

Info / 信息信息、品牌、进行中Blue
Success / 成功成功、完成、可用Teal
Warning / 警告注意、等待、需要处理Orange
Danger / 错误错误、危险、不可逆操作Red
Special / 特殊特殊分类或扩展状态Purple
状态色阶浅色状态背景优先使用 50–100，默认状态色使用 500，文字和高对比元素使用 600–700。
09 / BRAND GRADIENTS

品牌渐变规范

渐变以方案 C 的 blue/500 #176BFF 和 teal/500 #00D1B2 为主要端点。

渐变使用要求

  • 渐变不能代替成功、警告或错误等状态色。
  • 正文文字、表格文字和小尺寸图标不使用渐变。
  • 同一界面避免同时使用多种高强度品牌渐变。
  • 渐变上的文字和图标必须满足可访问性对比度要求。
  • 不随意改变已定义渐变的方向、端点颜色和色标位置。
  • Figma 中统一使用 Gradient/Brand/* Paint Styles。

优先使用既有 black-alpha/* 和 white-alpha/* 变量，不在组件中随意输入新的透明度。

11 / ACCESSIBILITY

可访问性要求

颜色组合需要在真实使用背景与最弱对比位置中验证。

正文文字≥ 4.5:1文字与背景
大号文字≥ 3:1文字与背景
重要图标与边界≥ 3:1与相邻颜色
  • 信息不能仅通过颜色表达，应同时使用文字、图标、形状或位置。
  • 错误状态必须提供明确的错误说明，不能只显示红色边框。
  • 渐变背景需要按实际最弱对比位置验证文字可读性。
  • 禁用状态仍需保持基本可辨识度，不应仅通过极低透明度表达。
12 / PROHIBITED

禁止事项

用明确边界避免临时颜色、含义漂移和视觉优先级冲突。

  • 不直接修改品牌核心色的 Hex 值。
  • 不在业务组件中写死 Hex、RGB 或临时颜色。
  • 不自行创建未进入基础色板的新颜色。
  • 不使用多个高饱和颜色争夺同一视觉层级。
  • 不将 Orange 和 Red 混用于同一种状态。
  • 不将 Red 用于普通装饰或常规重点信息。
  • 不在浅色背景上使用低对比度的浅色文字。
  • 不通过颜色单独表达错误、成功、选中或禁用状态。
  • 不随意改变标准渐变的方向和色标位置。
13 / EXAMPLES

正确与错误示例

通过明确示例统一颜色变量在业务界面中的使用方式。

✓ 正确

  • 主要操作使用品牌语义色，而不是直接填写 #176BFF。
  • 错误输入同时显示红色描边、错误图标和错误文字。
  • 成功提示使用 Teal，并配合“成功”文字或勾选图标。
  • 深色背景上的边框使用反色透明度变量。
  • 渐变仅用于品牌区域，正文区域保持稳定的纯色背景。

× 错误

  • 一个页面同时出现蓝、绿、橙、红四种同等级主按钮。
  • 用 Orange 表示错误，同时在其他页面用 Red 表示同类错误。
  • 使用 red/500 作为普通促销装饰颜色。
  • 在渐变背景上直接放置未经对比度验证的白色小字。
  • 为了接近视觉稿而创建 #186CFE 等临时近似色。

15 / MAINTENANCE

维护流程

Figma、CSS 和设计规范文档应同步更新。

  1. 新颜色必须先进入基础色板并说明新增理由。
  2. 业务使用场景通过语义变量映射基础色，不直接引用基础色。
  3. 修改基础色前，应检查所有语义变量和渐变样式的影响范围。
  4. Figma、CSS 和设计规范文档应同步更新。
  5. 每次修改后需要进行浅色模式、深色模式和关键状态的对比度复查。
  6. 未经评审的实验颜色仅用于探索稿，不进入正式变量集合。
